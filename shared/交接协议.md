# 写作与验收的交接协议

本文件只规定双方需要共同理解的输入、结果与状态。写作方法由写作入口管理，检查方法由验收入口管理；不以问题数量或修改次数衡量成效，不要求持续制造问题。

## 提交输入

写作方保存后按需提交：

- **检查类型与范围**：组织、支撑或修改后复验；首次完整验收先组织后支撑，仅检查请求按指定范围执行。
- **正文位置与提交标识**：提供绝对路径，以及能对应实际内容的标识，如版本号配合内容校验值。大纲、有效需求或相关依据变化也需说明。
- **有效用户要求**：读者、用途、范围、保留要求与材料边界。沿用大纲末尾的“用户需求”；重要约束保留必要用户原话，写作方推断另作说明。无大纲时直接提供所需要求。
- **必要原始输入**：大纲、原稿、材料和出处位置，明确固定材料或允许外部检索的范围，以及仍缺哪些输入。提供来源本身，不只提供写作方的摘要、核实结论或额外解释。
- **复验信息**：原问题、修改位置与可能关联范围。修改说明只帮助定位，不证明问题已经解决。

验收方从自己的职责、实际产物、用户要求和材料作判断，不以写作历史或完成声明作依据。正文意图不能靠附加解释补成已经表达清楚；无法独立读取必要输入时说明缺口。

## 版本与范围

检查期间保持提交输入稳定。验收方核对实际输入与标识；输入变化或读到混合版本时返回未完成并请求重新提交，不作通过结论。

结论只覆盖实际读取的版本、类型与范围。正文、大纲、需求或相关依据变化后，受影响的旧结论失效；修复后状态为待复验。验收方根据真实改动判断关联范围，不只按编辑者声明判断影响。

局部复验至少包括修改位置的完整段落、相邻承接与所用依据；影响分类、主线、核心结论或多处内容时检查全文。组织变化后的相关支撑结论也需重验。未受影响的成果与结论可复用，但说明适用范围，不以局部复验声称全文已检查。

## 检查结果

每轮说明提交标识、实际检查范围和所用依据，返回一种状态：

- **本轮通过**：适用内容已检查，未发现实际问题；仅对本轮类型与范围有效。
- **发现问题，待修复**：记录成立的问题与对应回退阶段。
- **待补充或决定**：必要输入、关键依据或作者判断尚缺，说明缺口和影响。
- **未完成**：读取范围未覆盖、工具或资源受限、输入变化等；说明已做与未做部分。

实际问题记录：位置及必要原文、具体缺口、判断依据、影响、对应回退阶段。复验保留原问题的对应关系，说明已解决、仍存在或有依据撤回，报告修改引入的新问题；未复验的问题继续保留。

只记录实际影响理解、事实、原意或逻辑，以及本轮相关用户要求落实的问题。另一种合理写法、个人偏好或未证实的疑虑，不足以新增必改目标。可给修复方向，不指定唯一文案，不提交替代正文；无需每句话生成记录，也不用评分或固定问题数量代替判断。

没有实际问题可以通过；缺少关键依据或检查未完成不能算通过。固定材料内的来源一致性检查与外部事实核验分开说明。

## 回退与问题关闭

| 问题性质 | 回退阶段 |
| --- | --- |
| 意图、边界不清或误读输入 | 准备第一、二步 |
| 主线、层级、重点安排不合理 | 准备第三步 |
| 依据或必要背景缺失 | 补充信息第四步 |
| 已有信息选取、解释、句间关系或推理有问题 | 内容编辑第五步 |
| 内容成立，但明确的个性化表达要求未落实 | 风格调整第七步 |

写作方只修复对应问题及关联内容，保存后重新提交；验收方检查真实新稿后确认关闭，写作方不能自行宣布解决。仅授权检查时只报告，不进入修复。

写作方可以提交原文、上下文、用户要求或材料依据提出异议；验收方独立回应，保留、修正或撤回问题，不忽略反证。双方在任务内处理分歧，不增加第三个裁判 agent；需要作者决定的立场或重要边界由主 agent 与用户沟通。未解决的实质问题不能记为通过。
