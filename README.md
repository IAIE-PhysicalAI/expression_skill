# 语言表达 · Chinese Expression

一份面向中文写作与润色的 Agent Skill，第一期聚焦技术分享文档：讲清一个技术或模型解决什么问题、如何工作、与其他方案有什么区别，以及如何判断它是否适合自己的场景。

围绕作者的核心想法选择信息、组织论证，在同一份文档上分阶段修改，让重点讲清楚、句间逻辑成立，并保留作者的语言风格。

**想法驱动，信息支撑。想法决定需要表达什么，逻辑决定如何组织与表达信息。**

当前示例与使用指南围绕模型介绍、技术机制解释和方案比较展开。技能主体、规则和使用提示均为中文，技术标识为 `chinese-expression`。

当前分支为 **v2.0.0 灰度版**（`gray/v2.0.0`），由原 `feature/staged-instructions-strict-mode` 分支重命名而来。正式版仍为 `main` 上的 **v1.1.0**。灰度版完整规则由入口文件与 9 份配套指令组成，版本号保存在 `SKILL.md` 的 `metadata.version` 中，详见[更新记录](CHANGELOG.md)。

[阅读当前灰度技能](skills/chinese-expression/SKILL.md) · [灰度测试指南](GRAY_TEST.md) · [下载 v1.1.0 正式包](https://github.com/IAIE-PhysicalAI/expression_skill/releases/tag/v1.1.0) · [反馈问题](https://github.com/IAIE-PhysicalAI/expression_skill/issues)

## v2.0.0 的变化

- 准备时在大纲中写清重点的判断或想揭示的问题，并注明段落或段落组借材料说明什么、承担什么承接作用。
- 用户需求集中保存在大纲文件末尾，纲要内部保留文章的结构与展开安排。追问中的局部改写持续更新原大纲和正文。
- 组织验收先从正文判断实际说明了什么，再对照大纲中的重点和段落作用；检查全文与各部分的主线，避免把事实罗列或结论出现过当成充分展开。
- 新增追问与修改职责，区分讨论、检查和实际编辑，按需要接续阶段并保护用户对当前稿的修改。

本版继续使用五阶段流程，内容编辑职责保持原有设计。上述变化尚待灰度任务验证；现有 v1.x 示例不代表 v2.0.0 的效果。

## 安装

### 安装 v2.0.0 灰度版

使用 Git 获取指定分支，再从本地目录安装，避免误装默认分支的正式版：

```bash
git clone --branch gray/v2.0.0 --single-branch https://github.com/IAIE-PhysicalAI/expression_skill.git expression-skill-v2
npx skills add ./expression-skill-v2 --skill chinese-expression --agent codex
```

也可以将克隆目录中的 `skills/chinese-expression/` 整个文件夹放入目标 agent 的技能目录。记录 `git -C expression-skill-v2 rev-parse HEAD` 的输出，以区分灰度期间的不同提交。本次通过分支分发，Releases 中的正式包仍为 v1.1.0。

更新灰度版时，在克隆目录执行 `git pull --ff-only` 后重新安装；升级前备份定制内容，回退时用 v1.1.0 正式包替换整个技能目录。旧分支使用者的迁移命令见[灰度指南](GRAY_TEST.md#旧分支迁移)。

### 使用 skills CLI 安装正式版

需要能够运行 `npx` 的 Node.js 环境。执行以下命令，再按提示选择使用的 agent：

```bash
npx skills add IAIE-PhysicalAI/expression_skill --skill chinese-expression
```

仅安装到当前项目的 Codex：

```bash
npx skills add IAIE-PhysicalAI/expression_skill --skill chinese-expression --agent codex
```

如需跨项目使用，在命令末尾添加 `--global`。安装位置由安装工具和目标 agent 决定。

安装前可以只查看仓库中可用的技能：

```bash
npx skills add IAIE-PhysicalAI/expression_skill --list
```

### 手动下载正式版

从 [Releases](https://github.com/IAIE-PhysicalAI/expression_skill/releases/latest) 下载 `chinese-expression.zip`，解压后将整个 `chinese-expression` 文件夹放入目标 agent 的技能目录。完整保留 `SKILL.md`、`references/`、`agents/` 和 `LICENSE`，不能只复制入口文件。附件 `SHA256SUMS.txt` 可用于核对下载包。

更新已有安装时，先备份自己的定制内容，再用新包替换整个技能目录。曾安装带严格模式的预览版时也采用整目录替换，避免遗留旧脚本或说明。v1.1.0 仅包含通用模式，使用它无需 Python 或独立调度器。

也可以点击 GitHub 的 **Code → Download ZIP** 下载仓库，技能位于 `skills/chinese-expression/`。不同工具的技能目录和刷新方式可能不同，请以对应工具的说明为准。

## 使用

安装后，在支持技能调用的 agent 中指定 `chinese-expression`。Codex 中可以使用 `$chinese-expression`；其他工具按各自的技能调用方式使用。

Agent 按阶段读取职责，在同一份工作文档上完成准备、补充信息、内容编辑、组织与逐句支撑验收、个性化风格调整。每个验收轮先读取职责，再重新读取已保存正文；修复后进入对应验收轮复查。

### 润色已有文档

```text
请使用 $chinese-expression 润色 technical-share.md。
目标读者是有工程经验、第一次接触这个技术的同事。
重点讲清核心机制、适用条件，以及与现有方案的差别。
保留我的立场与语言风格，先保存大纲，再分阶段修改。
生成 technical-share-polished.md，并保留原文件。
可以补充公开资料；无法核实的信息请单独说明。
```

### 基于固定材料成稿

```text
请使用 $chinese-expression，根据 notes.md 写一份模型技术分享。
读者是应用开发工程师，重点解释输入输出、核心机制和选型依据。
只使用输入材料，不新增外部事实、数据或真实案例。
按流程保存大纲和正文；材料不足以支撑的判断请指出。
```

### 开放式写作

```text
请使用 $chinese-expression 写一份关于 TypeSafe AI 的 Jev 的技术分享。
面向使用过大模型 API 的工程师，回答它与其他模型方案有什么区别。
重点解释输入输出、决策方式、概率与置信度，以及它在软件中的作用。
从同一个任务出发，比较结构化输出的语言模型、推理模型和专用分类器。
先确认问题并保存大纲，明确重点、标题层级和需要补充的依据。
根据大纲搜集可靠依据，在同一份工作文档上完成起草、校验和风格调整。
语言直接、具体，关键概念要解释，厂商声明与独立测评结论要区分。
```

提供原稿、目标读者、核心想法、材料边界和风格参考，有助于 agent 判断重点与详略。

### 追问与局部改写

```text
请使用 $chinese-expression 修改现有稿件的第二节。
这一节已有结论，但实验介绍没有说明它为什么支持该结论。
沿用当前正文和大纲，只调整这一节及必要的前后承接，保留数据和限定。
```

只要求讨论或检查时，技能交付分析；明确要求修改时才接续编辑。局部改写使用原有大纲，在相关条目落实结构与重点变化，将当前有效的用户需求保存在文件末尾。

## 工作流程

七个步骤按五个执行阶段组织，合并边界由技能明确规定：

| 阶段 | 对应步骤 | 需要完成的工作 |
| --- | --- | --- |
| 准备 | 一至三步合并 | 确认核心问题，理解材料，保存重点、段落作用和展开关系；文件末尾单列用户需求 |
| 补充信息 | 第四步独立 | 根据大纲中的重点观点再次检索与核实，记录依据、出处和缺口 |
| 内容成稿 | 第五步独立 | 确定每段核心，选择并组织信息，写入同一份工作文档 |
| 校验与修复 | 第六步独立 | 从正文判断主线与各段作用，再核对大纲；下一轮检查逐句支撑，发现问题后定向回退与复验 |
| 个性化风格 | 第七步独立 | 调整作者特有的语气、节奏和表达方式，保存并复查 |

大纲明确标题关系、重点想说明的判断或问题，以及段落或段落组的作用。背景和过渡交代服务对象，不必各自提出观点，也不预先固定所有自然段。用户需求单列在文件末尾，只维护当前有效要求；后续局部改写在原纲要中修改相关部分。

每轮修改针对具体问题。依据不足就补充材料，核心信息孤立就补足解释与关联，句间推理不成立就重新组织。已符合要求的内容保留，不为增加轮次而强行修改。

入口只保留阶段导航；详细职责放在 [references](skills/chinese-expression/references/阶段交接.md)，进入哪一阶段就读取哪份指令。全程表达原则共享，保存、回读、回退与复查集中到一份交接规则，不在每个步骤反复叠加。

任务目标用于理解文章方向，不转成固定观点、切入点、必写内容或评分表。验收仍采用技能已有的组织、解释、逻辑、支撑、事实与原意等判断条目，允许不同但成立的表达方案。

第六步也检查“不是……而是……”“并非……”等正反表达：保留理解所必需的区分与证据边界，将可直接表达的观点改为正面陈述，处理重复防备与虚设反方。此项随逐句验收执行，不设句式数量阈值。

## 中文表达规则

- 优先使用准确、熟悉的词汇；必要术语保留，并按读者需要解释。
- 删除重复与空泛内容，为重要但抽象的判断补足具体解释。
- 根据实际逻辑决定是否使用关联词，避免把相关、先后发生或用词相近写成因果与递进。
- 正面陈述优先，避免反复使用“不是……而是……”等防备性表达；必要的反面说明集中后置。
- 核实新增的事实、数据、引用与真实案例，保留原意、适用条件和确定性程度。
- 在全文、段落和句子三个层面检查信息是否支撑观点，避免关键概念、数据或判断孤立出现。

这些规则贯穿全程；最后的风格阶段处理作者个性化的表达特点。

## 环境与适用范围

技能使用通用的 [Agent Skills 格式](https://agentskills.io/)，核心指令位于 `SKILL.md`。`agents/openai.yaml` 提供 Codex 的展示信息；其他工具可能忽略该文件。

完整执行需要 agent 能读写文档；开放式写作和外部核验还需要搜索、读取来源的能力。技能本身不附带搜索服务、模型或文档编辑软件。仅有聊天输出的环境可以参考表达规则，但无法完整执行文件保存与回读流程。

通用模式依赖 agent 遵循阶段职责、重新读取文件并作判断；同一会话仍保留先前上下文。格式校验通过或完成流程不代表内容没有遗漏，涉及事实的最终稿仍需结合原始来源审阅。
