# Jev 决策模型在 Mobile GUI Agent 领域的研究进展

> 调研截止：2026-10-19；面向具有 GUI Agent 背景的研发同事。

## 1. 范围与结论

Jev 属于 typed decision model（TDM）：调用方提供状态、问题和有限候选，模型返回结构化选择及候选概率，不生成自由文本。厂商提供 Choice、Score、Noul 三类接口，并支持对同一状态的多个问题并行、隔离求值（[产品说明](https://docs.typesafe.ai/introduction.md)，[Choice 接口](https://docs.typesafe.ai/primitives/choice.md)）。这与 mobile GUI Agent 中“根据当前 UI 状态，从有限动作中选择下一步”的高频环节较为契合。

资料包所列定向检索并非穷尽检索。在其范围内，直接研究 Jev 与 mobile GUI Agent 的核心论文主要是 [Jev-Mobile](https://arxiv.org/abs/2609.30186v1) 和 [When Faster Decisions Do Not Make Better Agents](https://arxiv.org/abs/2610.13092v1)，且均为 2026 年 9—10 月的预印本。现有证据支持的结论是：Jev 可以成为受约束的快速执行层，但尚不足以替代 VLM 承担开放式规划、视觉定位和复杂恢复。局部决策更快、更便宜，能否转化为端到端收益，取决于候选覆盖、工作流开销、恢复能力和终态验证。

## 2. 研究思路分类

| 思路 | Jev 的角色 | 证据性质 |
| --- | --- | --- |
| 分层委派 | VLM 设局部目标，Jev 连续选择原子动作 | 直接 mobile GUI 实验 |
| 模块替换 | 替换既有 Agent 的动作选择器 | 直接、多工作流对照 |
| 视觉共享决策 | 共享截图编码，批量回答多个有限选择问题 | 机制相关，未做 mobile 端到端验证 |
| 端侧专用决策 | 小型 encoder 在设备侧完成候选评分 | 端侧可行性，非 GUI 控制证据 |
| 动态动作空间与恢复 | 组合候选、分支探索并按反馈修订 | 通用 Agent 证据 |

### 2.1 分层委派：低频规划、高频执行

[Jev-Mobile](https://arxiv.org/abs/2609.30186v1) 将系统拆成三层：VLM 读取任务、截图、accessibility tree 与历史，给出局部目标和精确输入文本；程序从当前树生成可执行候选；Jev 在候选 ID、`DONE`、`BLOCKED` 中反复选择。每次动作后都重新观察并生成候选，旧 ID 随即失效。一次 VLM 规划因此可以覆盖多步 GUI 操作，同时由程序约束动作的可执行性。

在完整 AndroidWorld 任务集上，Jev-Mobile 的成功率为 79%，SeeAct-V 为 78%，逐步 VLM 为 84%。除成功率外，该论文的时间和成本指标只统计成功轨迹：Jev-Mobile 平均总耗时 132.67 秒，比逐步 VLM 低 32.7%；平均全模型 API 成本为 0.072744 美元，低 73.4%；执行模型时间从 94.30 秒降至 5.16 秒。在该实验设置与统计口径下，完整系统显示出效率优势；但论文没有在同一委派框架下用小 VLM 替换 Jev，无法据此单独判断 Jev 是否优于其他轻量选择器。

这一路线的瓶颈首先是候选覆盖：accessibility tree 中不存在的纯视觉目标无法执行，长而嘈杂的树也会增加选择难度。其次，`DONE` 只表示局部控制权交还 VLM，并不等于任务完成；当前输入链路还不支持部分非 ASCII 文本。Jev 在这里是远程决策服务，“局部”指决策范围，并非端侧推理。

### 2.2 模块替换：局部节省如何传到任务层

[When Faster Decisions Do Not Make Better Agents](https://arxiv.org/abs/2610.13092v1) 将 Jev 接入 AndroidWorld 的 T3A、AutoDroid、FastAgent，以及 ALFWorld 的 ReAct、Reflexion，共执行 4,500 次。五个 Agent 家族的单次决策成本下降 66.1%—78.4%，决策时间下降 73.9%—81.5%；但三个移动 Agent 的成功率相对原配置分别下降 13.22、2.30 和 18.10 个百分点。

因此，per-decision latency 不能代表交付效率。辅助 LLM 调用、环境等待和额外交互会吸收节省；接口粒度变化还可能拉长轨迹。T3A 的每次尝试成本虽下降 17.1%，计入失败尝试后，单位成功成本反而从 68.70 mUSD 升至 73.97 mUSD；FastAgent 的单位成功时间从 239.4 秒升至 377.8 秒。轨迹分析还指向目标识别、前置条件、无效搜索、恢复失败和过早完成等问题。相关行为频次来自论文筛选的结果组，不宜外推为所有 mobile GUI 任务的普遍分布。

### 2.3 可迁移方向：视觉、端侧与动态候选

[Visual Jev](https://arxiv.org/abs/2609.25845v1) 共享同一图像的视觉前缀，并批量执行彼此隔离的问题后缀。每图 32 个问题时，其温启动摊销速度比串行执行快 8.9 倍、比重复前缀的批处理快 3.4 倍，但峰值显存更高。这可用于并行判断目标、页面状态和完成条件，不过论文没有 mobile GUI 端到端结果，厂商的图像与 Box 接口也仍标为试验功能（[图像文档](https://docs.typesafe.ai/images.md)）。

[Chinese-Jev](https://arxiv.org/abs/2609.36965v1) 的 INT8 模型在手机端约 1 秒完成一次决策，说明本地候选评分具有工程可能；其任务是通用及医法财中文决策，不能据此推断 GUI 控制能力。[JevSpawn](https://arxiv.org/abs/2610.00437v1) 用组合动作字段、并行分支、反馈修订和保留备选来缓解“候选必须预先给定”的限制；[Jev in RL](https://arxiv.org/abs/2610.11692v1) 则把 Jev 用作参考策略、探索判断器和 replay 评分器。两者均未在 mobile GUI 上完成专项验证。

## 3. 与 Mobile GUI 邻近路线的关系

最接近的非 Jev 路线是 [V-Droid](https://arxiv.org/abs/2503.15937v5)：它同样离散化动作空间，但用经过偏好训练的 LLM verifier 评价候选；Jev-Mobile 则使用通用 typed decision 服务并显式交接控制权。二者说明“候选生成 + 判别选择”是一条独立于逐步自由生成的路线，但实验设置不同，不能依据成功率直接排名。

其他工作处理的是互补瓶颈：[iSHIFT](https://arxiv.org/abs/2512.22009v1) 调节快慢视觉推理，[MobileExplorer](https://arxiv.org/abs/2605.26546v1) 在 VLM 推理期间并行探索，[MobileRL](https://arxiv.org/abs/2509.18119v2) 与 [UI-TARS-2](https://arxiv.org/abs/2509.02544v2) 强化多轮策略，[SeeClick](https://arxiv.org/abs/2401.10935v2) 聚焦视觉 grounding。基于这些互补能力，可优先验证一种组合式架构：Jev 处理结构证据充分、风险较低的高频选择；视觉 grounder 补足树外目标；慢 VLM 处理歧义与重规划；独立 verifier 检查终态。现有材料尚未对这一组合做统一实验。

## 4. 研发建议

短期应验证“选择性委派”，而非全量替换。只有当候选覆盖充分、目标与前置条件明确、动作后的状态变化可观察时才交给 Jev；低置信、连续无进展或树与截图冲突时升级到 VLM/视觉模型。候选描述应包含控件身份、前置条件和预期变化，并保留 `none/BLOCKED`。完成判断应与动作选择分离，防止局部 `DONE` 被误当成全局成功。

实验应在同一 controller、候选集和预算下，对照 Jev、小 VLM 与规则/打分器，并按任务难度和树覆盖率分层。除成功率和单次决策时延外，还应报告候选覆盖率、选择与交接正确率、恢复率、轨迹长度、失败开销，以及包含失败尝试的单位成功成本和时间。

总体上，Jev 在 mobile GUI 中最可信的定位是**工作流约束下的快速决策层**。直接证据仍少，模型闭源，系统接口与统计口径也不统一。[早期 TDM 证据审计](https://arxiv.org/abs/2609.32160v1) 同样认为，当前更清晰的收益在时延和成本，typed readout 尚未显示独立的准确率优势；该审计仅覆盖 Jev 发布后最初九天，也应视为早期证据地图，而非定论。
