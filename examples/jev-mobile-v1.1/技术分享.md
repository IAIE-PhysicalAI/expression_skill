# Jev 决策模型在 Mobile GUI Agent 领域的研究进展

> 调研截止：2026-10-19；面向具有 GUI Agent 背景的研发同事。

## 1. 范围与结论先行

Jev 是一种 typed decision model（TDM）：调用方给出状态、问题和有限候选，模型直接返回候选概率与结构化答案，不生成自由文本。厂商接口包括 Choice、Score、Noul，并强调同一状态上的多个问题可并行、隔离求值（[产品说明](https://docs.typesafe.ai/introduction.md)，[Choice 接口](https://docs.typesafe.ai/primitives/choice.md)）。它与 mobile GUI Agent 的契合点，是每一步通常都可表述为“在当前 UI 状态和有限动作集中选一个动作”。

但截至本次资料截止日，**直接研究 Jev 在 mobile GUI Agent 中应用的论文证据很少**：资料包中核心工作只有 [Jev-Mobile](https://arxiv.org/abs/2609.30186v1) 与 [When Faster Decisions Do Not Make Better Agents](https://arxiv.org/abs/2610.13092v1) 两篇，且均为 2026 年 9—10 月的新预印本。前者证明“低频 VLM 规划 + 高频 Jev 执行”可显著降时延和费用；后者通过更广泛的系统对照说明，局部决策变快并不保证任务成功或单位成功成本改善。因而当前最稳妥的判断是：**Jev 已显示为移动 GUI 的可用轻量执行器，但尚不能被视为通用替代 VLM 的成熟策略模型；候选覆盖、恢复和完成验证决定了效率能否兑现。**

## 2. 研究思路分类

| 思路 | Jev 所处角色 | 代表工作 | 当前证据 |
|---|---|---|---|
| 分层委派执行 | VLM 定局部目标，Jev 连续选原子动作 | Jev-Mobile | 直接 mobile GUI 证据，效率突出、成功率略降 |
| 原工作流内替换 | 用 Jev 替换现有 agent 的动作选择模块 | Faster Decisions | 直接、多 agent 对照；收益高度依赖工作流 |
| 视觉共享决策 | 一次编码截图，多问题批量判断 | Visual Jev | 与 GUI 感知高度相关，但非 mobile agent 端到端验证 |
| 端侧专用决策 | 小型 encoder、本地推理、语言/领域适配 | Chinese-Jev | 证明端侧可行性，未验证 GUI 控制 |
| 自适应动作空间与恢复 | 动态构造有限字段、分支搜索、反馈修订 | JevSpawn 等 | 通用 agent/RL 证据，可作为移动 GUI 后续设计参考 |

### 2.1 低频规划、高频结构化执行

[Jev-Mobile](https://arxiv.org/abs/2609.30186v1) 将任务理解与动作执行拆开：通用 VLM 读取截图、无障碍树和历史，生成局部目标及精确输入文本；程序从当前 accessibility tree 枚举可执行候选；Jev 在候选 ID、`DONE`、`BLOCKED` 中反复选择。每次动作后重新观察并重建候选，避免旧坐标或旧 ID 静默绑定到新页面。VLM 因此可用一次规划覆盖多步 GUI 操作。

在完整 AndroidWorld 上，该系统成功率为 79%，接近 SeeAct-V 的 78%，低于逐步 VLM 的 84%。仅在成功轨迹上统计时，平均总耗时为 132.67 秒，相比逐步 VLM 降低 32.7%；全模型 API 平均成本由 0.273694 美元降至 0.072744 美元，降低 73.4%；执行模型时间从 94.30 秒降至 5.16 秒。这里真正有效的不是单纯“小模型替大模型”，而是三层约束：VLM 缩小语义范围、程序保证动作可执行、Jev 只做当前状态下的有界选择。

局限同样清晰：accessibility tree 缺失的纯视觉目标无法进入候选集；长而嘈杂的树会增加选择难度；当前输入链路不支持部分非 ASCII 文本；`DONE` 仅表示局部交接，不等于任务完成。该论文也未设置“同一分层框架下用小 VLM 替换 Jev”的控制组，因此无法完全分离 Jev 模型与委派架构本身的贡献。

### 2.2 在既有 Agent 中替换动作选择器

[Faster Decisions](https://arxiv.org/abs/2610.13092v1) 把 Jev 接入 AndroidWorld 的 T3A、AutoDroid、FastAgent，以及 ALFWorld 的 ReAct、Reflexion，共进行 4,500 次执行。所有五个 agent 的单次决策成本下降 66.1%—78.4%，决策时间下降 73.9%—81.5%；但 AndroidWorld 上 Jev 版本相对原版成功率分别下降 13.22、2.30、18.10 个百分点。T3A 虽然单次尝试成本下降 17.1%，按全部失败开销折算后，单位成功成本反而从 68.70 mUSD 升至 73.97 mUSD；FastAgent 的单位成功时间从 239.4 秒升至 377.8 秒。

这组结果揭示了三类“效率传导损失”：一是辅助 LLM 推理、环境等待和额外交互吞掉选择器节省；二是一步一个工具等接口变化拉长轨迹；三是目标识别错误、前置条件违反、无效搜索、恢复失败和过早完成降低交付率。尤其在移动端，短任务也会因选错语义含混的开关后直接宣告完成而失败。因此评测不应只看 per-decision latency 或成功轨迹均值，还应同时报告全任务成功率、失败开销、匹配成功样本，以及 cost/time per delivered success。

### 2.3 视觉、端侧与自适应决策：有潜力但尚非直接证据

[Visual Jev](https://arxiv.org/abs/2609.25845v1) 面向“同一图像上的多项独立选择”：共享图像前缀，批量执行隔离的问题后缀。在每图 32 个问题时，其温启动摊销速度比串行执行快 8.9 倍、比重复前缀的批处理快 3.4 倍，但峰值显存更高；训练后宏平均准确率由 70.6% 升至 76.1%，增益集中于训练覆盖的任务族。它适合未来把“目标定位、页面状态、完成条件、风险判断”作为并行 GUI 判定，但资料没有端到端 mobile GUI 结果。厂商图像与 Box 接口仍标为试验性质（[图像文档](https://docs.typesafe.ai/images.md)），不宜视为生产级 grounding 结论。

[Chinese-Jev](https://arxiv.org/abs/2609.36965v1) 以轻量 encoder 做中文候选评分，INT8 手机端约 1 秒/决策，说明隐私敏感、离线 mobile agent 的本地决策层具备工程可能；但其评测是通用及医法财决策，不是 UI 状态理解或动作执行。[JevSpawn](https://arxiv.org/abs/2610.00437v1) 则动态组合动作字段，以并行分支、反馈选择、表示修订和保留备选支持恢复，回应了“Jev 需要预先给定有限候选”的核心限制；不过资料中的八项 benchmark 并未建立 mobile GUI 专项结论。[Jev in RL](https://arxiv.org/abs/2610.11692v1) 将 Jev 用作参考策略、探索判断器和 replay 评分器，为训练 GUI policy 提供了另一条路线，但实验仅覆盖 MiniGrid 与 Atari。

## 3. 与主流 Mobile GUI 路线的关系

Jev 路线并非孤立的新范式，而是“生成式全能 agent”之外的结构化判别路线。最接近的非 Jev 对照是 [V-Droid](https://arxiv.org/abs/2503.15937v5)：它离散化动作空间，用 LLM verifier 对候选动作做 pair-wise progress 判断，AndroidWorld 成功率 59.5%，每步 4.3 秒。两者共同表明“候选生成 + 判别选择”可以替代逐步自由生成；差异在于 V-Droid 通过偏好训练强化 verifier，而 Jev-Mobile 依赖通用 typed decision 服务与显式交接。

其他路线优化的是不同瓶颈：[iSHIFT](https://arxiv.org/abs/2512.22009v1) 在快/慢视觉推理与感知区域间自适应切换；[MobileExplorer](https://arxiv.org/abs/2605.26546v1) 利用 VLM 等待时间并行探索并回滚；[MobileRL](https://arxiv.org/abs/2509.18119v2) 与 [UI-TARS-2](https://arxiv.org/abs/2509.02544v2) 通过多轮 RL 提升端到端策略；[SeeClick](https://arxiv.org/abs/2401.10935v2) 聚焦截图 grounding。它们提示一个更实际的组合方向：Jev 负责低风险、有充分结构证据的高频选择，视觉 grounder 补足树外目标，慢 VLM 处理歧义与重规划，verifier 检查终态，RL/轨迹数据训练恢复策略。

## 4. 研发判断与建议

短期最值得验证的是“可选择性委派”，而非全量替换：仅当候选覆盖充分、目标和前置条件明确、预期状态变化可观测时交给 Jev；低置信度、连续无进展、树与截图冲突时升级到 VLM/视觉模型。候选描述应显式包含控件身份、可用条件、动作后预期变化，并把 `none/BLOCKED` 作为一等选项。完成判断应独立于动作选择，至少检查关键终态或让 verifier 复核，避免局部 `DONE` 被误当成任务成功。

实验上应在同一 controller 内做 Jev、小 VLM、规则/打分器的等接口对照，并按任务难度和树覆盖率分层；同时记录候选覆盖率、选择准确率、交接正确率、恢复率、轨迹长度、全量成本及单位成功成本。对于中文与端侧场景，还需单独验证中文控件语义、输入能力、量化后的校准和真实设备延迟。

总体而言，Jev 在 mobile GUI 中最有价值的定位不是“更小的端到端 Agent”，而是**被工作流严格约束的快速决策层**。现有证据已支持其显著降低局部执行成本，但系统收益取决于上游候选质量和下游验证/恢复。由于直接论文仅两篇、模型闭源、基线与统计口径不完全一致，当前结论应视为早期工程证据，而不是已定型的领域共识；这一判断也与早期 TDM 证据审计所述“主要优势在时延与成本，typed readout 尚无独立准确率优势”一致（[Early Evidence Audit](https://arxiv.org/abs/2609.32160v1)）。
