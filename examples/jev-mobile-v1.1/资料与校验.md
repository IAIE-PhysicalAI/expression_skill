## 统计口径校验

1. P01：成功率的分母是全部任务；时间与成本行仅统计成功轨迹。执行模型成本 `0.013091` 美元是成功轨迹 cohort 总和，不是单轨迹均值；正文不使用该数，以免混淆。
2. P02：`cost/time per delivered success` 用所有尝试（包括失败）的总资源除以成功数，适合衡量实际交付；与 P01 的“成功轨迹均值”不是同一口径。
3. P02 的“所有五个 agent”指五个 agent 家族（AndroidWorld 三个、ALFWorld 两个）；实验配置数量更多。正文避免写成“五个移动 agent”。
4. P01 与 P02 的模型版本、动作接口、预算和系统边界不同；数值只在各自论文内部比较。
5. P11 等摘要结果来自不同论文和实验设置，仅用于路线定位，不做横向排行榜。

## 已确认的材料缺口

- 材料包不是系统综述，无法证明未收录数据库中不存在其他 Jev/mobile GUI 研究。
- P01 没有同一委派框架下的小 VLM、规则模型或其他选择器等接口对照，无法把架构收益完全归因于 Jev。
- P02 的移动端配置均为文本观察；材料不支持把结论直接外推到视觉原生 GUI agent。
- P03、P04、P05、P06 没有 mobile GUI 端到端实验，均只能列为可迁移研究方向。
- 厂商模型闭源；当前材料不足以解释 Jev 内部机制，也不足以确认产品文档之外的生产稳定性。
