## 怎样保证初稿没有参考本技能

1. **重新生成初稿。** 不使用仓库原有文章，也不让已经读过技能的主会话模拟“不使用技能”的写法。
2. **隔开上下文。** 两次执行均为全新会话，不继承当前对话；初稿目录只放任务和参考资料，不放技能、旧文或润色目标答案。
3. **检查自动注入。** 关闭已发现技能的自动加载及相关插件入口，检查运行前的模型可见消息，确认没有本技能的名称、描述、正文及技能目录列表。
4. **原样冻结。** 初稿生成后直接保存为 Git 提交，并核对文件哈希；不故意写差，不人工删改，不生成多篇后挑选差的一篇。
5. **只在修订阶段提供技能。** 将初稿和相同资料复制到另一目录，加入当时版本的 `SKILL.md`，由修订会话按技能分阶段修改。发布者不再手工改写正文。

独立会话和目录用于隔开任务上下文，读写范围通过指令限制并结合工具记录检查；这不是操作系统级的文件访问隔离。“没有参考”特指本次执行未加载这份自定义技能，不代表模型训练中从未见过相似写作方法。

## 怎样理解这个结果

这是一次真实的使用示例，不是技能效果的因果实验。初稿也可以正常查阅资料、自查和修改，不刻意限制其能力；修订阶段额外获得一次编辑机会和技能指导，因此不能把全部变化都归因于技能。

本轮只运行一个初稿和一次技能修订，没有挑选最佳结果。没有增加“同样再润色一次、但不使用技能”的对照组，也没有跨模型重复试验或盲评。若要证明稳定提升，需要进一步补齐这些比较。

资料范围固定，避免把“修订者拿到了更多事实”混入对比。该示例验证的是固定材料下的信息选择、组织、解释和校验，不验证开放式检索，也不包含 Jev API 实测。事实边界和仍待核实的事项见配套记录。
