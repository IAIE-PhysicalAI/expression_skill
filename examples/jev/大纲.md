# Jev 技术分享大纲

## 写作任务

面向使用过大模型 API、第一次接触 Jev 的工程师，回答：Jev 的决策接口与常见模型方案有什么区别，这些区别如何影响系统设计和选型？

核心想法：从同一个“读取用户消息并决定处理路径”的任务出发，解释 Jev 的输入、受限输出和不确定性表达，再比较生成模型、推理模型和专用分类器。比较应落到开发者需要设计的接口、判断依据和执行流程。

依据以 TypeSafe 官方文档为主，模型供应商关于架构、训练和性能的描述应明确归属。本文不进行 API 实测，不给出未经验证的速度或成本排名。

## 一、Jev 接受什么、返回什么【重点，详细展开】

### 1. 状态与问题

解释 state 提供判断材料，questions 定义需要回答的问题；用软件支持场景贯穿正文。

### 2. 选择、评分与概率

介绍文本决策中的 Choice、Score、Noul，解释返回值如何被代码使用。受限答案空间与自由生成的差别在这里说明。

## 二、这些接口背后的模型差别【重点，详细展开】

### 1. 与采用结构化输出的语言模型比较

承认语言模型也能返回合规的结构化结果。比较输出约束和训练目标，解释格式保证、事实正确与概率校准是不同问题。

### 2. 与推理模型比较

解释窄问题判断与多步问题求解的分工，说明多个独立问题可以并行，存在依赖的问题仍需由代码分阶段组织。

### 3. 与专用分类器比较

围绕同一分类任务比较：标签与判定标准如何提供，是否需要任务训练，如何验证概率。说明分类器本来就能输出概率，避免把概率输出写成 Jev 独有能力。

三个子标题比较的是三类常见实现方案，能力可能重叠，不将它们包装成互斥的模型谱系。每种方案内部都按“判断任务—输出与约束—系统影响”展开。

## 三、如何理解概率并接入业务【重点，详细展开】

### 1. 概率、置信度与校准

解释概率对应候选答案；confidence 是分布的摘要；校准需要在一组预测上验证。用三选一的示意分布解释两类数字的不同，所有人为数字注明不是实测。

### 2. 一个从输入到动作的完整流程

用支持请求说明独立判断、代码检查、阈值路由与人工复核如何衔接。解释模型提供判断信号，程序负责执行条件；不给出通用阈值。

## 四、如何决定是否采用【简要交代】

总结适合尝试的任务、应交给其他方案的任务，以及最小评估方法。采用相同样本和输出要求比较正确性、自动处理覆盖率、端到端耗时和成本，不从宣传倍数推出普遍结论。
