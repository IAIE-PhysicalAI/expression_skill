# Jev 与其他模型有什么区别？从一次软件决策说起

一条用户消息进入系统后，程序可能需要判断它属于哪个业务、是否紧急，以及要不要交给人工。这些判断的结果会直接影响下一步执行。Jev 面向的就是这类任务：开发者提供待判断的状态和一组问题，模型返回限定答案空间内的选择、评分或概率，程序再据此分支、排序或路由。

TypeSafe AI 将 Jev 称为其首个 **System One Model**。这个名称强调快速、范围明确的判断；Jev 可以理解自然语言，但不生成文章、代码或推理解释。理解它的价值，需要同时看输入输出、训练目标和它在软件中的职责。[1][2]

## 一、一次 Jev 调用包含什么

### 状态提供材料，问题定义判断

假设用户发来一条消息：“我的订阅被扣了两次费，请帮我处理。”应用可以把消息、已经查到的交易记录和相关业务规则一起放进 `state`，即本次判断所依据的状态。开发者另外提供 `questions`，说明想知道什么，以及允许的答案是什么。[1][3]

例如，问题可以是“应由哪个支持团队处理”，候选答案为账单支持、技术支持和其他。候选项需要有清楚的描述，让模型知道“订阅扣款问题”归属于哪个类别。输入中提供了什么证据、选项是否覆盖实际情况，都会影响这个判断是否有用。

### 三种文本决策，各有不同的返回值

下面三种问题覆盖了选择、等级评价和是非判断。它们的数字承担不同含义。[3][4][5]

| 问题类型 | 应该问什么 | 主要返回值 | 程序如何使用 |
| --- | --- | --- | --- |
| Choice | 应由账单支持、技术支持还是其他团队处理？ | 选中的项、每个选项的概率、confidence | 选择处理路径，也可以根据概率分布决定是否复核 |
| Score | 问题严重程度处于哪个等级？ | 分数、等级说明、各等级的概率、confidence | 按预先定义的严重程度排序 |
| Noul | 用户是否明确要求退款？ | “是”的概率，范围为 0 到 1 | 按业务阈值进入后续流程 |

Choice 的选项没有高低顺序；Score 的等级有顺序。例如，把问题严重程度描述为“功能正常，仅外观异常”“功能受损，但有替代办法”“完全阻断，且无替代办法”，分别对应 0、1、2。Score 的分数是等级编号按概率加权后的平均值，可以落在两个等级之间。假设三个等级的概率为 0、0.6、0.4，分数就是 `0 × 0 + 1 × 0.6 + 2 × 0.4 = 1.4`。这表示结果处在后两个等级之间，且更偏向“有替代办法”。这里的数字是计算示例。

Noul 则直接回答一个是非问题。在“用户是否明确要求退款”这个问题上，接近 1 的值表示模型更倾向于“是”。当前文档中的 Noul 没有单独的 `confidence` 字段，不能把 Choice 的返回结构套用到所有问题上。

## 二、与常见模型方案相比，差别在哪里

实际开发中，可以用结构化输出的语言模型、推理模型或针对任务训练的分类器完成部分相同工作。下面按三种实现方案比较；它们的能力可以重叠，例如推理模型也可能支持结构化输出。

### 与结构化输出的语言模型：输出约束与训练目标

语言模型同样可以把“应由哪个团队处理”写成结构化结果。以 OpenAI 的 Structured Outputs 为例，开发者可以用 JSON Schema 限定字段、类型和枚举项，让成功返回的结构化结果符合接口要求。[8]

在接口都能满足程序要求的前提下，还要比较训练与概率的含义。TypeSafe 将自己的训练方法称为 **RLCD（Reinforcement Learning for Calibrated Decisions，面向校准决策的强化学习）**，公开说明的目标是输出决策和能够反映不确定性的概率。这是厂商披露的训练方向；此处引用的资料尚不足以复现完整算法。[7]

这涉及三个分别需要检查的问题。格式正确，意味着程序可以按约定读取结果；判断正确，意味着它与实际情况相符；概率校准，意味着预测概率与长期观察到的结果频率相符。在语言模型的结构化输出中加一个名为 `confidence` 的数字字段，只规定了接口形状，还需要验证该数值有什么依据。OpenAI 文档也明确说明结构化输出仍可能包含错误。Jev 的概率以校准为训练目标，同样需要在具体业务数据上检查表现。[7][8]

如果现有语言模型已经能完成需要的分类，并且还要同时生成解释或回复，结构化输出方案值得保留为比较基线。Jev 是否更合适，应通过同一任务上的结果决定。

### 与推理模型：复杂问题在哪里拆解

推理模型适合需要多步分析的任务。例如，要综合交易记录、条款例外和前后矛盾的信息，判断一项复杂的退款争议，可能需要先查资料、比较解释，再形成判断。以 OpenAI 的推理模型为例，它们会使用内部推理词元（reasoning tokens）进行中间分析，考虑不同解法，支持规划、多步求解和工具使用。这些推理词元也会占用上下文和计费额度。[9]

Jev 的官方建议是把任务拆成单个、范围明确的判断，再由代码组合答案。回到支持请求，可以分别询问“用户是否要求退款”“提供的记录是否显示重复扣款”“是否缺少处理所必需的信息”。这些问题共同帮助程序决定下一步。[1][2]

同一请求中的多个问题按官方说明独立地读取同一份状态。如果第二个问题需要第一个问题的结果，就要由程序接收结果、更新状态，再发起后续判断。把独立问题放在同一请求中，也不能省去有依赖关系的步骤。

这里的系统设计选择是：哪些问题已经足够清楚，可以直接判断；哪些仍需要搜索、多步分析或人工解释。复杂流程可以同时使用两类模型。

### 与专用分类器：判断标准由什么提供

逻辑回归、树模型或经过任务微调的文本分类器，也可以把输入映射到预设类别，其中许多方法本来就支持概率输出。对于标签固定、标注数据充足的任务，这类方案应当参与比较。概率是否可信仍需验证，scikit-learn 的校准文档专门讨论了这一点。[10]

Jev 的接口允许开发者在请求里用自然语言描述问题与候选标准。相比为一个具体标签体系训练的分类器，这提供了另一种表达任务的方式：标准可以随请求传入。不过，调整描述会改变判断条件，效果仍要重新评估。[3][4]

选型时可以分别检查两种投入：专用分类器需要怎样的数据与训练维护，Jev 需要怎样的上下文、选项描述和验证样本。哪种方式更省维护成本、质量更稳定，取决于任务和现有数据。

## 三、概率怎样变成程序可以使用的信号

### 概率、confidence 与校准分别表示什么

沿用“应由哪个团队处理”的 Choice 问题。假设返回的单题结果如下，数值仅为说明而设，未经 API 实测；这里省略了完整响应的外层字段：

```json
{
  "type": "choice",
  "choice": "billing",
  "probabilities": {
    "billing": 0.80,
    "technical": 0.15,
    "other": 0.05
  },
  "confidence": 0.70
}
```

`probabilities` 表示模型在这些候选答案之间分配的概率。这个例子中，账单支持的概率最高，为 0.80。

`confidence` 是 TypeSafe 从概率分布计算出的摘要。按其 Choice 公式，候选项数量为 `n`、最高概率为 `p_max` 时，`confidence = (p_max - 1/n) / (1 - 1/n)`。三个候选项、最高概率 0.80，对应的 confidence 就是 0.70。因此，这两个字段不能互换，也不能把 confidence 0.70 直接解释为“这次答案有 70% 的正确率”。[6]

校准需要观察一组预测。假如模型对许多类似案例都给某类结果约 0.80 的概率，校准良好意味着这些案例中，该结果出现的比例也接近 80%。这是一种统计关系，不能保证某次判断正确，也不能直接证明模型在新业务上仍然校准良好。[2][7][10]

### 程序如何组合判断与执行条件

在这个支持场景中，一条完整的处理流程可以这样组织：

1. 程序读取用户消息，并查询可用的账户与交易数据，构成判断状态。
2. Jev 返回处理类别，以及是否要求退款、是否存在重复扣款迹象等独立判断。
3. 程序结合答案、不确定性和确定性业务检查，决定转账单团队、继续补充资料或送人工复核。
4. 真正涉及资金操作时，执行代码继续检查权限、交易状态及金额等条件。
5. 需要向用户说明处理结果时，再使用模板或生成模型组织回复。

这个流程中，“消息提到了重复扣款”和“交易系统确认重复扣款”是两种不同证据。前者帮助识别诉求，后者才与实际交易有关。把两者区分清楚，才能避免从语义分类直接跳到业务动作。

如何设阈值，要看误判的代价以及真实数据上的表现。验证时可以观察：提高自动处理门槛后，错误路由是否减少，人工复核量增加多少。这样才能选出适合当前业务的阈值。[6]

## 四、如何决定是否采用 Jev

先选一个答案空间清楚、结果可以验证的任务，例如支持请求分类、文本条件判断或按明确标准评分。若任务还要求生成长文、代码或推理解释，需要为这部分安排具备相应能力的模型。已有规则或专用分类器能稳定完成的任务，也应作为基线。

用相同测试样本、相同判断标准和相同输出要求比较方案。除了正确率，还要看概率与结果是否相符、在可接受错误水平下能自动处理多少案例，以及整个流程的延迟和成本。将补充检索、重试和人工复核纳入统计，才能判断 Jev 对系统的实际价值。本文没有做这些实测，因此不提供速度、价格或质量排名。
