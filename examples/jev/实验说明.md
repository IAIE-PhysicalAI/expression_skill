# Jev 润色对比：实验条件与复现

本例使用一个未加载本技能的独立会话生成初稿，再让另一个独立会话使用技能润色。展示入口是[同一文档的 Git diff](../润色示例.md)，不是两篇各自生成的文章。

## 固定条件

| 项目 | 本次执行条件 |
| --- | --- |
| 执行日期 | 2026-10-18 |
| 工具 | Codex CLI 0.154.0，两个全新 `codex exec` 会话，不使用 resume 或 fork |
| 模型配置 | 两次均使用当时默认的 `ferry-gpt-5-6-sol`，推理强度 `medium`；这是网关配置别名，不是对后端精确版本的独立认证 |
| 任务 | 向有大模型 API 使用经验的工程师介绍 Jev，与其他模型方案比较；正文约 2000 个汉字，允许适度调整 |
| 资料 | 同一批 10 份官方文档的本地文本快照，来源及 SHA-256 见[来源清单](实验/来源清单.json) |
| 原稿 | 初稿会话第一次完整运行的产物，未经发布者改写；允许该会话正常自查 |
| 修订 | 初稿副本、相同资料、原有任务，加上 `SKILL.md`；不提供旧示例、标准答案或预设修改点 |
| 轮数 | 初稿一次，技能修订一次；未挑选结果或因效果不理想而重跑 |
| 发布 | 两个会话的正文按字节保留，配套说明由发布者另行编写 |

模型服务有随机性，网关别名也可能变化；复跑流程不保证逐字复现。相同配置不等于能够独立证明服务端每项参数始终相同。

## 上下文隔离

两次执行分别使用独立工作目录。初稿运行前，目录中只有 `prompt.txt` 和 `sources/`；修订目录额外包含初稿副本和本次技能文件。两者均不继承当前聊天内容，也不提供仓库中既有的 Jev 示例。

运行配置对本机发现的技能目录及 `SKILL.md` 路径设置 `skills.config` 的 `enabled=false`，并关闭 `plugins`、`apps`、`skill_search`、`memories` 和 `multi_agent`；设置 `project_doc_max_bytes=0`、`web_search="disabled"`，执行时使用 `--ignore-rules`。这些均为本次命令行覆盖，不修改用户全局配置。

执行前用 `codex debug prompt-input` 检查相同配置下的可见消息，未发现 `chinese-expression`、技能核心原则或自动注入的技能列表。修订会话随后通过文件读取显式加载本地 `SKILL.md`。禁用技能自动发现不妨碍按用户要求读取这份文件。

两次运行使用相同的附加开发者约束：

```text
只读写当前工作目录及其子目录中的任务文件。不要读取其他目录，不联网，不调用其他 agent，不使用任何目录外的技能或旧文章。使用 apply_patch 修改文件。
```

这是指令和事后工具记录层面的隔离，不是操作系统级沙箱。本例没有把“模型承诺未参考”作为唯一证据，也不声称能够证明模型训练中从未接触过类似内容。

公开操作记录保留执行顺序、命令、文件变更和阶段进度，省略原始文档输出及内部推理内容；本机绝对路径归一化为相应工作目录。原始日志的哈希用于识别该次运行，不意味着读者能仅靠哈希自行验证未公开日志。

## 从 Git 精确还原对比

克隆仓库后，在仓库根目录执行：

```bash
git show d9ec2757a3d1e1262d4f1851a397688d3e3f0f22:examples/jev/技术分享.md
git show 9709d7939a458dac9fcd2a79cddaf1b41450a966:examples/jev/技术分享.md
git -c core.quotepath=false diff --no-ext-diff --no-textconv \
  d9ec2757a3d1e1262d4f1851a397688d3e3f0f22 \
  9709d7939a458dac9fcd2a79cddaf1b41450a966 \
  -- examples/jev/技术分享.md
```

`润色对比.diff` 直接来自这两个提交的 `git diff`，没有手工拼接红绿行。初稿文件哈希、修订文件哈希和差异文件哈希均记录在运行记录中。两次提交之间只修改正文，点击 GitHub 对比不会混入安装说明或实验记录的变化。

## 复跑写作流程

1. 另建干净工作目录，按来源清单准备资料；记录抓取时间及哈希。若使用的 agent 会自动加载技能、全局写作规则或记忆，先关闭并检查实际注入内容。
2. 新开会话，提供初稿提示词和资料；正常完成写作后冻结结果，不手动改差，也不挑选结果。
3. 新建修订目录，放入原样初稿、相同资料和固定版本的技能。另开会话，提供修订提示词；让它按技能在同一正文上实际保存、读取和修改。
4. 保存两边原始产物、提示词、配置和操作记录，用 Git 提交或 `git diff --no-index` 生成真实差异。
5. 报告具体变化与未解决问题。若要归因于技能，再补一个“相同初稿、相同资料、同样编辑机会，但不使用技能”的修订对照，并做多样本盲评。

本例限定资料范围，覆盖技能在固定材料润色中的行为；不能据此验证外部检索效果、Jev 当前全部产品能力或任何模型的性能排名。

## 发布者复核与已知问题

以下是在两次生成结束后进行的复核，不是给修订会话的追加提示，也没有回写到实验正文中。

- **有具体改善。** 概率、`confidence` 和校准从同一长段拆开，新增“校准针对一组预测”的解释；删除没有展开的“上下文腐化”；将部分比较结论收敛到已有材料支持的范围。工具记录显示确实保存了大纲与材料记录，再改正文、回读、修复，并在风格修改后再次读取。
- **产品能力说明仍不可靠。** 两稿采用了资料包中 System One 概念页的“仅支持文本”。发布前另查[Images](https://docs.typesafe.ai/images.md)与[Box](https://docs.typesafe.ai/primitives/box.md)，官方已描述 Jev 1.13／1.14 的实验性图像输入，以及需 Jev 1.14 的 Box；它们需要显式开启，且尚未达到生产标准。这与概念页的绝对表述有差异。本次固定材料包未包含这些页面，修订会话也未获准联网补充，因此未消除该问题。不要把实验正文当作 Jev 当前完整能力指南。
- **解释仍可补足。** Score 示例说明了概率加权均值，但没有明确写出等级编号从 0 开始及 `0×0 + 1×0.57 + 2×0.43 = 1.43`，读者仍需补出计算前提。`confidence` 的概括也没有展开 Score 对等级距离的考虑。
- **大纲同步未完全落实。** 正文将“分类器都能输出概率”收敛为“有些”，并调整了 Choice 选项边界的表述，大纲仍保留较强的旧说法。配套记录中的“校验通过”是执行 agent 的自评，不等于独立审查结论。

这些问题原样保留并公开说明，以免把“按技能执行了流程”包装为“结果已经完全正确”。后续改进技能或追加联网修订，应作为另一次明确标记的实验，不覆盖本次对比起点与终点。
