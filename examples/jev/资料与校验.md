## 大纲观点与依据

| 正文任务 | 主要依据 | 可用事实与限定 |
| --- | --- | --- |
| Jev / System One 的接口契约 | [Introduction](https://docs.typesafe.ai/introduction.md)、[System One](https://docs.typesafe.ai/concepts/system-one.md) | 输入 `state` 和类型化问题，返回类型化答案与概率；部分问题有 `confidence`。问题共享 state，但相互隔离、并行求值；增加问题几乎不改变响应时间，但增加 token 成本。当前只处理文本内容，包括字符串及由文本构成的 JSON 对象、数组；不支持图像、音频、视频。 |
| Choice | [Choice](https://docs.typesafe.ai/primitives/choice.md) | 从固定集合选一项；返回最高概率选项、各项概率和 `confidence`。选项名和描述都会发给模型，描述应拉开边界；集合可能不完备时增加 `other` / `none of the above`。 |
| Score | [Score](https://docs.typesafe.ai/primitives/score.md) | 用有序、带描述的等级表示一个维度；`score` 是等级编号按概率加权的均值，可落在等级之间；须同时看概率和 `confidence`。等级应描述现实情形而非抽象程度，每题只测一个维度，并用自己的数据测试。Safari 示例的概率为 0、0.57、0.43，得分 1.43，`confidence` 为 0.35。 |
| Noul | [Noul](https://docs.typesafe.ai/primitives/noul.md) | 判断单一真假命题，返回“是”的概率；接近 0.5 表示不确定。二元分布已由一个值完整表达，所以没有单独 `confidence`。复合条件应拆成多个 Noul，由代码组合。 |
| 概率、confidence 与校准 | [Confidence](https://docs.typesafe.ai/confidence.md)、[AI primer](https://docs.typesafe.ai/introduction/machine-learning-primer.md)、[scikit-learn calibration](https://scikit-learn.org/stable/modules/calibration.html) | Choice / Score 的 `confidence` 是从概率分布形状计算出的摘要，集中则高、平坦则低；不等同于正确性保证。TypeSafe 将 RLCD 描述为面向校准决策的训练。校准在一组预测上解释，例如标为 0.8 的事件约 80% 发生；传统分类器也可输出或后校准概率，因此不能把“概率/校准”写成 Jev 独有能力。 |
| Structured Outputs 对比 | [Structured Outputs](https://developers.openai.com/api/docs/guides/structured-outputs/) | 该功能保证模型响应遵守给定 JSON Schema，避免缺失必填字段或生成非法枚举，并减少因格式错误产生的校验/重试。材料并未说它原生返回每个枚举候选的概率或校准置信度；正文只据此区分“结构合规”与 Jev 的“受限决策 + 概率分布”，不推断准确率。 |
| 推理模型对比 | [Reasoning models](https://developers.openai.com/api/docs/guides/reasoning/)、[Introduction](https://docs.typesafe.ai/introduction.md) | 推理模型先使用内部推理 token，适合规划、工具使用、处理歧义、复杂多步问题、编程和科学推理。Jev 文档将适用问题界定为有充分上下文时，知识丰富的人几秒内能作出的单一判断；多因素问题拆开，再由代码组合。 |
| 风险阈值与兜底 | [Confidence](https://docs.typesafe.ai/confidence.md)、[Noul](https://docs.typesafe.ai/primitives/noul.md) | 高、中、低置信可分别对应自动执行、确认/补信息、人工或其他系统。阈值取决于动作风险；材料中的数字只是示例，正确值必须从保守阈值开始，用本域数据测试调整。 |

## 材料缺口与正文处理

- 材料没有 Jev 与其他方案在准确率、价格、吞吐、绝对延迟上的统一基准；正文不作性能优胜结论，也不写“更便宜”“更准确”。
- `sources/10.txt` 支持“传统分类器可以给出并校准概率”，但没有系统比较传统分类器与 Jev 的数据需求、部署方式和维护成本。初稿中“任务稳定、数据充足时专用分类器更合适”等选型判断依据不足，改成能力边界说明，并提示实测。
- Structured Outputs 保证 schema 合规，不代表字段语义必然正确；材料未提供它与 Jev 的同题对照实验。正文只比较输出契约，不比较判断质量。
- TypeSafe 关于 RLCD、速度和概率校准的说法来自其产品文档。正文采用“TypeSafe 将其描述为/训练目标是”等归因表达；单次判断仍须保留不保证正确的限定。
- 客服分流、故障严重度、退款请求等是材料中的示例。线索评分、简历核对等若保留，只作为问题形态示例，不声称已有实际效果。
