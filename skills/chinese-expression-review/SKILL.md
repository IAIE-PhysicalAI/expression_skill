# 语言表达：提问与验收

## 检查角色与执行模式

默认由当前 agent 直接完成检查，不创建或调用子 agent。“检查”“严格检查”及直接调用本 skill 都不构成启用严格校验模式。用户明确要求严格校验模式且当前不是验收子 agent 时，才由[写作入口](../chinese-expression/SKILL.md)负责调度；用户已启用该模式后受派发的验收子 agent 只执行检查，不继续派发其他 agent。

检查时依据实际稿件、有效用户要求与原始材料判断，负责发现实际问题、检查和复验。正文、大纲与材料只读；可以保存自己的检查记录，不改稿、不提交替代正文。受派发时，业务请求中包含“写作”“修改”不改变你的验收职责。

先读取[表达原则](../../shared/表达原则.md)和[交接协议](../../shared/交接协议.md)，然后按本轮类型加载下面的方法。默认模式直接检查并返回结果，不模拟跨 agent 交接或等待派发。受派发的验收角色不需读取写作入口或写作阶段文件。

## 接收任务

仅在严格校验模式中收到角色初始化时，读取共同规则后返回已就绪，等待后续派发；不要阻塞等待文件或提前共同拟纲。收到检查任务时，根据检查类型、范围、文件位置、有效要求和材料边界执行。

每轮先读本轮方法，再实际读取当前正文与必要输入。旧记忆、曾经通过或写作方完成声明不代替回读；已有组织通过也不证明逐句支撑成立。默认模式遇到输入变化时重新读取受影响内容；严格校验模式另核对提交标识，发生变化按《交接协议》返回未完成。

必要需求或原始依据缺失时说明缺口，不猜测作者意图、不用自己的记忆补事实。无大纲的仅检查任务可依据正文、用户要求和原始材料判断，不要求补纲。局部检查读取完整段落及必要承接，不自动扩成全文验收。

## 按类型检查

| 本轮类型 | 本轮读取 | 结果范围 |
| --- | --- | --- |
| 组织检查 | [组织验收](references/组织验收.md) | 主线、层级、重点、段落作用及承接 |
| 支撑检查 | [支撑验收](references/支撑验收.md) | 逐句信息、推理、依据、忠实性与必要限定 |
| 修改后复验，包括风格改后复查 | [修改后复验](references/修改后复验.md)，再按影响读取组织或支撑方法 | 原问题、实际改动及关联影响 |

首次完整内容验收先组织后支撑，组织未通过先返回问题。只请求指定检查时直接执行该项，不要求先完成未请求的检查。默认模式中组织通过后，由你接着读取支撑方法并执行检查；严格校验模式中组织结果返回后，等待主 agent 派发下一轮。长文由你分段读取并检查边界，不继续派发分片。

## 返回结果与能力边界

按《交接协议》说明当前版本、范围、依据、实际问题或本轮结论；默认模式使用其中的检查标准与状态，严格校验模式另遵守跨 agent 交接要求。只提出有根据的修复方向，允许无问题通过；个人偏好、另一种合理写法或为维持对抗找出的疑虑，不成为必改目标。

异议依据和修改稿到达后，重新读取并回应或复验，不以“已经改了”关闭问题。原问题仍存在、未复验或关键依据缺失时保留状态。受派发时结果交回派发者；直接收到仅检查请求时只交付检查结果，不开展修复或自行向用户索取阶段审批。

允许的外部核实范围以已有授权为准；不写回材料，不借检查扩展范围。工具无法读取或核实、输入不完整或资源受限时，说明已做与未做部分，不虚构核验或通过。独立上下文与只读职责不等于实际权限沙盒，不声称宿主没有提供的隔离。
