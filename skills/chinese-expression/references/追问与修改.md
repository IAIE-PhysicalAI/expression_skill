# 追问与修改

用于接续已有稿件上的讨论和修改。先理解用户这次希望改什么、达到什么效果、保留什么，再由相应阶段完成修改；持续使用同一份工作稿。

## 识别请求并读取当前内容

用户只询问含义、依据或修改理由时，读取回答所需内容后直接解释。用户只要求讨论、比较写法或检查问题时，交付相应分析，不据此写回文档。用户提出修改要求，或结合上下文已经明确表达修改意图时，接续编辑；仅补充材料而未说明用途时，结合上下文判断其作用，不自动把全部材料加入正文。

每次接续编辑前，实际读取已保存的当前工作稿。结合对话定位“这一段”“刚才那句”等指代；位置明确时直接使用，实质歧义才询问。当前文件可能包含用户自行作出的修改，不能以记忆或聊天中展示的旧文本覆盖它。

- 局部修改读取目标所在完整段落、必要的前后承接及相关大纲；不能仅搜索一句话后直接替换。
- 涉及章节关系、主线、读者或全文风格时，按判断和修改需要扩大读取范围，必要时读取全文及完整大纲。读取范围不等于允许改写的范围。
- 初始原稿和原始材料用于核对原意、事实、材料边界或作者原有风格，涉及这些判断时按需重读。当前工作稿仍是编辑起点，不用初始原稿覆盖已经成立的修改。
- 后续阶段读取自己的最新输入，验收与复验按《阶段交接》重新读取保存后的真实内容。

## 必要时与用户确认

结合用户请求、当前内容、原稿或参考文本及已有明确偏好，判断修改要求是否足够清楚。只有不同理解会实质改变语气方向、原意、读者定位、修改范围或重要约束时，才暂停相关修改并询问。

从实际存在且无法可靠推断的问题中，选择对本次修改影响最大的至多三项；只有一项就问一项。问题的顺序由具体任务决定，不预设通用优先级。多种合理写法本身不构成询问理由，已有答案不重复确认。

说明需要用户决定的事项及其对修改的影响，不先生成候选正文让用户挑选。收到回复后据此确定修改要求并推进，无需再请用户审批接续阶段。

## 选择接续阶段并落实修改

对照当前成果与用户要求，判断具体差距以及哪个阶段负责解决。以实际工作需要选择阶段，不按“润色”“补充”“自然一点”等词语机械映射。多个相互依赖的阶段受影响时，从最早需要调整的阶段开始；仍然有效的大纲、材料和正文直接复用。

| 需要完成的工作 | 接续阶段及用户要求的落实方式 |
| --- | --- |
| 修正作者想法、读者、用途、材料边界或对输入的理解 | 准备第一、二步：用用户补充或确认的信息修正理解，更新相关写作安排；其余仍成立的安排保留 |
| 调整主线、层级、归属或重点详略 | 准备第三步：修改相关大纲，写清该部分要说明什么、如何展开，再检查由此产生的材料需要 |
| 补充、提取、核实或替换依据 | 补充信息：把用户要求落实为具体信息缺口，在原有材料范围内查找，按已有授权开展外部检索，保存依据及其用途 |
| 已有信息足够，需要重新选择、解释或组织 | 内容编辑：对照用户期望定位当前表达的不足，调整相关段落的信息、解释、顺序或句间关系，写回当前正文 |
| 内容成立，只需调整语气、节奏、句式或作者声音 | 个性化风格：依据用户偏好及参考表达调整对应文字，保留事实、限定与原意；进入条件仍遵守风格阶段要求 |
| 用户要求检查结构、逻辑、支撑或忠实性 | 内容验收：执行相应检查，不预先假定正文有错；仅要求检查时报告结果，已授权修改的任务中再交回负责修改的阶段 |

进入对应阶段后，读取该阶段职责、当前成果及必要材料，将用户本轮要求作为这次工作的具体目标：明确哪里需要改变、期望效果是什么、哪些内容必须保留，再按本阶段职责操作。要求不应被扩写为用户未提出的立场、固定答案或必写句子。

例如“这一段再自然一点”：若实际需要调整语气和节奏，由风格阶段处理；若生硬来自解释跳跃，由内容编辑补足已有信息之间的关系；若仍缺少依据，先进入补充信息。判断以当前文本及必要确认结果为依据。

追问引导的局部改写沿用原有大纲文件，不另建局部大纲或重建整份大纲。按《准备》的落盘规则更新文件末尾的“用户需求”；结构、重点与段落作用有变化时，仅修改原纲要中的相关部分。依据保存到原有材料记录，内容和风格写回同一工作稿。各阶段处理必要的承接，保留仍有效的信息与表达。

## 让后续阶段使用修改成果

仅在实际需要按用户要求调整的阶段明确具体修改任务。其他阶段读取更新后的大纲、材料或正文，重新完成自己的职责；不要求每轮重新设置、复述或加载整份修改说明，也不强制建立独立状态文件。

交接按需说明修改位置、需要复查的关联范围和未解决问题；后续阶段从大纲文件末尾读取相关用户需求，包括成果中不易看出的保留要求与修改边界。

验收继续使用原有通用标准，并检查与本阶段相关的用户要求是否落实；通用标准与本次要求都要满足。验收独立性体现在依据实际成果作判断，不能把编辑者的完成声明当作通过依据。无需另建验收失效表。

发现旧问题依然按《阶段交接》交给对应阶段常规修复，不因其属于旧问题而忽略，也不另立特殊轮次。确认出现新的实际问题时，说明具体缺口、影响及需要解决的事项，再交给对应阶段定向处理；仅有疑似问题或个人写法偏好不足以新增修改目标。两者都保持编辑与验收分离，写回后重新验收。

最终验收通过后直接交付保存并复查的版本，无需再询问是否满意或要求用户审批。仍依赖缺失材料或作者决定的问题按《阶段交接》处理，不能记为通过。
