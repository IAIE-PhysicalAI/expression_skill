# 阶段交接

## 统一边界

1. 准备阶段合并第一至三步；补充信息、内容编辑、内容验收和个性化风格分别执行。第六步内部按组织、逐句支撑的顺序检查；编辑与验收不在同一轮承担。
2. 下一轮从已保存的当前正文、大纲和所需材料开始，不从上一轮的记忆继续。编辑轮写回同一正文；验收轮只报告判断，不直接改稿。
3. 每轮只加载基础原则、本轮职责和必要任务材料。普通会话可按需读取但无法清除已进入的上下文；严格模式由调度器为各轮建立独立调用，不传递聊天历史或编辑者的通过声明。
4. 大纲随结构、重点和关键限定调整；内容变化后，相关旧验收不能沿用。修复后重新读取并检查问题与关联内容，影响主线时检查整体。
5. 风格调整后重新检查受影响内容。严格模式保守地对当前全文再次执行组织与支撑检查，避免自动猜测修改影响范围。

## 问题与回退

只记录实际影响理解、事实、原意或逻辑的问题：位置、具体缺口、影响及对应回退步骤。可以提出有依据的修复方向，但不指定唯一正确文案。不要求每句话生成记录，也不用打分表代替判断。

| 问题 | 回退 |
| --- | --- |
| 意图、边界不清，或误读输入 | 准备：第一、二步 |
| 主线、层级、重点安排不合理 | 准备：第三步 |
| 依据或必要背景缺失 | 补充信息：第四步 |
| 已有信息选取、解释、句间组织或推理有问题 | 内容编辑：第五步 |

修复只处理对应问题和关联内容，沿后续阶段返回验收，不机械重做无关部分。修改完成只能标记为待复验；验收轮根据实际内容确认是否解决。存在新问题则继续定向回退。

## 结束与交付

无问题或无修改需要时直接通过，不强求改动次数。关键依据缺失或作者判断待确认时，标明未解决事项与影响，不能算作通过。达到预设资源上限时暂停并交付当前状态，不把超限解释为完成。

交付已保存并复查的正文与大纲位置；默认不向读者展示内部全过程。清理正文中的修改说明、对话应答、占位符和服务邀约，不在最终回复中另写未经检查的新版本。
