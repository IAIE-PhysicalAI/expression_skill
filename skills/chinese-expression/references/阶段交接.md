# 阶段交接

这里的“轮”指一次承担指定阶段职责的执行，不是等待用户发送下一条消息。条件满足后继续进入下一阶段；只有确需用户补充信息或作出决定时才等待。

## 统一边界

1. 准备阶段合并第一至三步；补充信息、内容编辑、内容验收和个性化风格分别执行。第六步内部按组织、逐句支撑的顺序检查；编辑与验收不在同一轮承担。
2. 每个验收轮先读取本轮职责，再重新读取已保存的当前正文及必要的大纲、材料。正文已在上一轮进入上下文不能代替本轮回读；验收轮只报告判断，不直接改稿。
3. 每轮只加载基础原则、本轮职责和必要任务材料。同一会话无法清除已有上下文，阶段独立依靠职责边界、文件回读和重新判断；不得声称已经实现上下文隔离。
4. 大纲随结构、重点和关键限定调整。内容变化后，相关旧验收失效；修复完成后必须重新进入对应验收轮，不能由编辑轮自行宣布通过。
5. 复验先重新读取保存后的真实内容。局部修改至少检查修改位置、完整段落及相邻承接；影响分类、主线、结论或多处内容时，重新读取并检查全文。不能只搜索修改句确认它已经出现。
6. 风格调整后重新检查受影响内容；若改变事实、原意、条件、推理或结构，回到相应内容验收。

## 问题与回退

只记录实际影响理解、事实、原意或逻辑的问题：位置、具体缺口、影响及对应回退步骤。可以提出有依据的修复方向，但不指定唯一正确文案。不要求每句话生成记录，也不用打分表代替判断。

| 问题 | 回退 |
| --- | --- |
| 意图、边界不清，或误读输入 | 准备：第一、二步 |
| 主线、层级、重点安排不合理 | 准备：第三步 |
| 依据或必要背景缺失 | 补充信息：第四步 |
| 已有信息选取、解释、句间组织或推理有问题 | 内容编辑：第五步 |

修复只处理对应问题和关联内容，不机械重做无关部分。修改完成只能标记为待复验；新的验收轮按本轮职责重新读取文件，确认原问题是否解决并检查修改影响。存在新问题则继续定向回退。

追问修改中发现的旧问题同样可以交回责任阶段常规修复。确认出现新的实际问题时，明确其缺口和影响后设置相应修改任务。两者都由负责修改的阶段处理，验收轮不直接改稿；用户要求如何进入各阶段见[追问与修改](追问与修改.md)。

## 结束与交付

无问题或无修改需要时直接通过，不强求改动次数。关键依据缺失或作者判断待确认时，标明未解决事项与影响，不能算作通过。达到预设资源上限时暂停并交付当前状态，不把超限解释为完成。

最终验收通过后直接交付已保存并复查的正文与大纲位置，无需再次询问用户是否满意或请求审批。默认不向读者展示内部全过程。清理正文中的修改说明、对话应答、占位符和服务邀约，不在最终回复中另写未经检查的新版本。
