# 严格执行模式

## 作用与边界

程序约束执行流程，不将文章观点、切入点和结构变成固定答案。组织与支撑检查仍采用本技能原有原则，由模型作语义判断；“程序执行完成”不等于事实绝对正确，也不保证遗漏率为零。

调度器每轮启动一个新进程，只发送全程表达原则、阶段交接、本轮职责，以及原任务、原始正文、当前正文／大纲、材料和未解决问题。不发送对话历史或上一轮“已通过”的解释。当前稿和原稿用于保持连贯与作者声音。

固定顺序：准备 → 补充信息 → 内容编辑 → 组织验收 → 支撑验收 → 风格调整 → 组织复查 → 支撑复查。后两轮是第七步修改后的检查，不增加写作步骤。发现问题按原因回退准备、补充信息或内容编辑，再沿顺序回到验收；已有合适内容可不改。

## 运行

需要 Python 3.11+；默认适配器需要已安装并登录的 Codex CLI，支持 `exec --ephemeral --output-schema` 和 `debug prompt-input`。沿用当前模型和认证配置，不指定新模型，不修改全局配置。调用会消耗已配置模型的额度；完整无修复流程为八次阶段调用。

在项目中准备 `任务.txt`、正文和可选的材料文件，然后执行以下命令，将脚本路径替换成实际安装路径：

```bash
python3 /path/to/chinese-expression/scripts/strict.py \
  --document ./技术分享.md \
  --task ./任务.txt \
  --material ./资料.md \
  --work-dir ./技术分享.expression-run
```

`--document` 是原地迭代的目标；开始前备份原正文和大纲。需要保留原文件不变时先建立工作副本并将副本作为目标。新写作允许正文不存在。大纲默认使用同目录的 `技术分享.大纲.md`，也可通过 `--outline` 指定。

材料参数可重复，省略时仅使用原稿与任务提供的信息。当前严格模式不自动联网：补充阶段在输入材料中重新检索、提取依据，不足时返回暂停。开放式任务先在用户授权范围内取得可追溯资料再运行；这项限制不改变通用模式的按需外部检索能力。

记录目录首次运行必须为空，包含初始备份、材料笔记、`run.json` 与逐轮文本 diff。不要把这些含原文的记录上传到公开仓库，除非用户明确同意。

## 写入与验收控制

| 阶段 | 允许提出的修改 |
| --- | --- |
| 准备 | 大纲 |
| 补充信息 | 材料笔记 |
| 内容编辑 | 正文和大纲 |
| 组织／支撑验收及复查 | 不允许修改正文、大纲或笔记 |
| 风格调整 | 正文 |

模型返回精确的文本替换候选，由调度器验证匹配位置与阶段权限后写回。空匹配仅用于创建空文件；位置不唯一、越权修改、错误阶段或过期版本均被拒绝，整批候选不会应用。

文档、大纲、任务、材料及技能引用的版本共同绑定本轮结果。调用期间输入改变则拒绝写回；检查意见只能作用于所读版本。调用进程不能通过返回“完成”跳过后续阶段。修改轮无法直接关闭问题，只有后续验收通过才会清除待复验列表。

默认 Codex 适配器使用临时目录、只读沙箱，关闭工具入口、自动技能目录、插件、记忆和配置中的 MCP 服务，并检查自动注入。模型只提交 JSON；正文写权限留在调度器。保留用户现有命令规则和认证配置。CLI 不兼容时停止，不回退到一次性写作。

调度器不是通用安全沙箱：它严格控制协议结果的接纳和自己的写入行为，不能约束同一操作系统账户下恶意的自定义适配器或其他进程。输入哈希提供变更检测，不替代操作系统文件权限；不要在运行中同时人工改稿。

## 暂停、上限与恢复

- 缺材料或需作者判断：`paused`，退出码 2，保留当前稿和问题；不宣布通过。
- 超过 `--max-repairs`：`limit`，退出码 2。默认允许三轮定向修复；不是要求必须修改三轮。
- 协议错误、超时或输入变更：`error`，退出码 1，本轮候选不写回。之前已完成的修改保留。
- 全部检查完成：`complete`，退出码 0，只表示本次流程与模型检查完成。

恢复时重复原命令并加 `--resume`。相同输入从中断阶段继续；正文、材料或规则发生变化则从准备阶段重新建立当前状态，旧验收失效。可显式提高 `--max-repairs`，但不会自动增加额度。若要加入新的材料路径，使用新的记录目录；恢复要求原有路径不变。

`--timeout` 控制单轮适配器秒数；`--max-input-chars` 控制完整请求字符数。超限停止，不截断正文或伪装已读全篇；长文先划定合理处理范围或显式调整上限。

运行目录有锁，避免并发调度。进程被强制结束后若遗留 `.lock`，先确认记录的进程不再运行再移除，不能直接启动第二个写入者。

## 自定义适配器

通过 `--adapter-command 'python3 /absolute/path/adapter.py'` 指定可信适配器。每轮在新临时目录启动，标准输入是一个 JSON 请求，标准输出必须是一个 JSON 响应；诊断输出写标准错误，不夹杂正文或 Markdown 代码围栏。

请求包含 `stage`、`revision`、`instructions`、`input`、`pending_issues` 和 `response_schema`。必须新建模型会话，不恢复历史，也不主动加载额外技能。程序只保证新进程，不能证明自定义适配器内部没有复用远端会话。

响应必须完整符合请求附带的 schema：

```json
{
  "stage": "compose",
  "revision": "原样返回请求版本",
  "decision": "ok",
  "changes": [{"target": "document", "before": "原文中的唯一片段", "after": "替换后的片段"}],
  "issues": [],
  "note": "本轮修改范围及尚需注意的事项"
}
```

`decision` 为 `ok`、`revise` 或 `blocked`；`revise` 必须提供问题，含 `location`、`problem` 和 `return_to`。不把自由形式的 `note` 当成程序可证明的语义质量。使用自定义适配器时自行负责权限、数据去向和上下文隔离。
