# 严格校验模式

仅在用户明确要求使用严格校验模式后读取并执行本文件。普通写作、检查、复杂任务或规则讨论不启用此模式。该模式由写作主 agent 和一个提问／验收子 agent 完成，全程只有这两个执行者。

## 初始化与复用

开始严格校验流程时，创建或复用本任务的一个提问 agent。正文尚未形成时只初始化角色，后续再派发具体检查。

- 派发时提供[验收入口](../../chinese-expression-review/SKILL.md)的绝对路径，并明确本任务已由用户启用严格校验模式、其提问角色、必要原始要求和可读取资源范围。让它读取自己的入口和共同规则；不转交完整写作历史、候选稿比较或写作方的自我评价。
- 使用不继承父会话历史的方式；当前工具支持时设置 `fork_turns: "none"`。若宿主不能选择，尽早在写作前创建、限制后续交接并说明实际继承范围，不声称历史已清除。模型与推理强度沿用用户或适用配置。
- 保存提问 agent 的标识。组织、支撑、修改后复验及后续追问都向这个 agent 派发，空闲时触发新执行，运行时等待当前轮结果。不为检查类型或修复轮次另建 agent。

初始化说明应包括：你是本任务唯一的提问／验收子 agent，先读取指定验收入口，完成初始化后返回等待；不得修改正文、大纲或材料，不得派发其他 agent。不要让初始化任务阻塞等待尚未形成的稿件。

## 提交与问题关闭

保存产物后，按[交接协议](../../../shared/交接协议.md)提交当前版本、检查类型、范围、有效要求和必要原始依据。检查期间保持提交文件稳定。材料尚未保存时先保存原始输入或提供可独立读取的来源；不要用自己的摘要或核实声明替代来源。

首次完整内容验收先提交组织检查；修复并复验通过后再提交支撑检查。风格调整前需有相关范围内仍有效的组织与支撑通过结论，实际改动后提交修改后复验。仅检查请求只派发指定范围，不自行扩大任务。

写作方的材料核对和自检仍需认真完成，但不代替本模式的独立验收。修复保存后只能标记待复验；提问方确认原问题及修改影响后才可关闭。异议提交原文、上下文或材料依据，由提问方回应；不增加第三个裁判 agent。

提问方完成所需检查，结论仍覆盖交付版本且无未解决实质问题，才可交付为独立验收通过。检查后再次改动，重新提交必要复验。

## 能力边界与退出

缺少子 agent 调度能力或独立验收未完成时，继续能完成的写作与自检，并说明严格校验未完成及实际限制，不模拟独立验收或将自检称为独立验收通过。独立上下文和只读职责不等于宿主提供了权限沙盒。

用户要求单 agent 或退出严格校验时，停止后续派发，由当前 agent 接续检查与修复；需要结束仍在运行的检查时使用宿主提供的停止能力。保留已有有效结论和未解决问题，不因切换模式跳过必要复查。
